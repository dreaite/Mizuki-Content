## **1．実験目的**

- IPパケットの形式を理解し、各フィールドの意味と長さを把握する
- `tcpdump`と`wireshark`を使用したパケットのキャプチャおよび解析技術を習得する

## **2．実験環境**

- ハードウェア要件：Alibaba Cloud ECSインスタンス1台。
- ソフトウェア要件：Linux／Windowsオペレーティングシステム

## **3．実験内容**


### **3.1** **tcpdumpの基本的な使用方法**


tcpdumpは、ネットワークパケットをキャプチャし、その内容を出力するツールである。強力な機能と柔軟なキャプチャ方式を備えており、UNIX系システムにおけるネットワーク解析やトラブルシューティングで広く使用されている。


tcpdumpは、ネットワーク層、プロトコル、ホスト、ネットワーク、ポートによるフィルタリングに対応している。また、and、or、notなどの論理演算子を使用して不要な情報を除外できる。

### **3.2** **wiresharkの基本的な使用方法**


Wireshark（旧称Ethereal）は、ネットワークパケット解析ソフトウェアである。ネットワークパケットをキャプチャし、可能な限り詳細なパケット情報を表示する機能を持つ。WiresharkはWinPCAPをインターフェースとして使用し、ネットワークカードと直接データパケットを送受信する。


ネットワーク管理者はWiresharkを使用してネットワークの問題を検出し、ネットワークセキュリティエンジニアは情報セキュリティ関連の問題を調査する。開発者は新しい通信プロトコルのデバッグに使用し、一般ユーザーはネットワークプロトコルに関する知識を学ぶために使用する。

### **3.3** **tcpdumpによるパケットキャプチャとwiresharkによる解析**


Alibaba Cloudインスタンス上でコマンド `traceroute www.xju.edu.cn –T` を実行し、`tcpdump`を使用してパケットをキャプチャする。ファイルをローカルマシンにダウンロードし、`wireshark`で解析する。


**ヒント：**1. 最初にパケットキャプチャコマンドを実行し、その後で経路追跡コマンドを実行する必要がある。パケットキャプチャコマンドは `tcpdump -i eth0 -w test.cap` である。


2. `scp`コマンド、または`xshell`と`xftp`を使用して、パケットデータをローカルマシンにダウンロードできる。


1) `tcpdump`でパケットをキャプチャし、`wireshark`でキャプチャしたパケットを解析する。`IP`パケットの構造を解析し、`IP`プロトコルツリー内の各フィールド名、フィールド長、フィールド情報を次の表に記入する。


| **フィールド名**                       | **フィールド長** | **フィールド値**       | **フィールドが表す情報**                                         |
| ----------------------------- | -------- | ------------- | -------------------------------------------------- |
| バージョン                       | 4bit     | 4             | 使用されている IP プロトコルのバージョン番号を示す                                    |
| IPヘッダー長              | 4bit     | 20            | 使用されている IP プロトコルのバージョン番号を示す                                    |
| 差別化サービスフィールド | 8bit     | 0x00          | より良いサービスを提供するために使用される。旧規格ではサービスタイプと呼ばれ、パケットの優先度を示すためのフィールドだったが、実際には使用されてこなかった。 |
| 全長                  | 16bit    | 40            | IP パケット全体の長さを示す                                     |
| 識別子               | 16bit    | 0x6f33        | パケットを識別するための ID 番号                             |
| フラグ                          | 3bit     | 0x40          | 後続のフラグメントが存在するかどうかを示す                                        |
| フラグメントオフセット               | 13bit    | 0             | 分割されたパケットの、元のパケット先頭位置に対するオフセットを示す                              |
| 生存時間                  | 8bit     | 64            | 「データグラムが通過できるルーター数」の上限を設定する。「ホップ数」とも呼ばれる。                   |
| プロトコル                      | 8bit     | 6             | ネットワーク層より上位で使用されているカプセル化プロトコルを示す                                 |
| ヘッダーチェックサム               | 16bit    | 0x9d2c        | ヘッダーの正当性を検査し、IP ヘッダーデータの破損を防ぐ                            |
| 送信元                        | 32bit    | 172.16.2.237  | 送信元 IP アドレス                                            |
| 宛先                   | 32bit    | 100.100.27.15 | 宛先 IP アドレス                                           |


2) `wireshark`を使用して、関連する`traceroute`コマンドの実行結果を解析し、解釈する。


**ヒント：**`wireshark`のフィルターツールバーを、`ICMP`のみ表示するように設定する。

| **フィールド名**                       | **フィールド長** | **フィールド値**       | **フィールドが表す情報**                                                    |
| ----------------------------- | -------- | ------------- | ------------------------------------------------------------- |
| バージョン                       | 4bit     | 4             | 0100 .... = バージョン: 4                                        |
| IPヘッダー長              | 4bit     | 20            | .... 0101 = ヘッダー長: 20バイト (5)                       |

> 解析結果：
>
> `ICMP`メッセージは、`ICMP`エラー報告メッセージと`ICMP`問い合わせメッセージの2種類に分類される。キャプチャ中に出現したICMPメッセージのタイプは、いずれも`Time to live exceeded in transit`であり、生存時間を超過したことを示している。任意の`ICMP`メッセージを1つ選択して確認すると、この`ICMP`メッセージは`Type=11,Code=0`であり、エラー報告メッセージに属することから、生存時間の超過を示している。チェックサムは`0x4e4d`で、結果は正しく、チェックサムの状態も良好である。また、`TTL`は4である。
>

## **5、実験のまとめ**


### **5.1 問題と解決方法**

> 問題：tracerouteコマンドを使用した際に、-bash: traceroute: command not foundというエラーが発生した。解決方法：yum install tracerouteコマンドを使用して、最初にtracerouteをインストールする。
> 問題：Xftpでサーバーに接続した際に、接続エラーが発生した。解決方法：学内ネットワークに接続すると正常に戻った。調査の結果、サーバーのファイアウォールが原因であることが判明した。

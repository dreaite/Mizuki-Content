## **3．Experiment Content**


UDP (User Datagram Protocol) is a connectionless transport-layer protocol that provides simple, unreliable, transaction-oriented message delivery services. It serves many application-layer protocols, including the Network File System (NFS), Simple Network Management Protocol (SNMP), Domain Name System (DNS), and Trivial File Transfer Protocol (TFTP). Unlike TCP, UDP does not provide reliability mechanisms, control, or error recovery for the IP protocol. Because UDP is relatively simple, its header contains few bytes and incurs less overhead than TCP.

### **4.2** **Based on the experiment results, what components make up a UDP datagram, and what are their functions?**


From the data obtained in the experiment, we can see that the main body of a UDP datagram consists of two parts: the UDP header (8 bytes) and the UDP data/UDP payload. The UDP header consists of the source port number, destination port number, packet length, and checksum.


Each of the four fields in the UDP header occupies two bytes (16 bits). Their functions are as follows:

> Source port number  
> Transmitting the source port number helps the server-side application determine the origin of the datagram. Destination port number  
> Transmitting the destination port number enables the destination host to deliver the application data to the corresponding process running on the destination port (that is, to perform demultiplexing). Length  
> The length field indicates the number of bytes in the UDP segment (header plus data). Because the length of the data field in a UDP segment is not fixed, a length field is required to facilitate processing by the receiving program. Checksum  
> The receiver uses the checksum to verify whether errors have occurred in the segment.

コンピュータシステムは、ハードウェアとシステムソフトウェアで構成され、両者が連携してアプリケーションプログラムを実行します。

```c
#include<stdio.h>
int main(){
    printf("hello world! C");
    return 0;
}

```

プログラムhello.cのライフサイクルを追跡する—\>作成、実行、出力、終了。

# 1 情報＝ビット＋コンテキスト

hello.cは**ソースプログラム**であり、helloプログラムの出発点となる、プログラマーが作成したテキストファイルです。これはバイト（8個のビットを1組としたもの）で構成されます。

その大部分では**ASCII規格**が使用されます。プログラムはバイト列としてファイルに保存され、各バイトの整数値が1つの文字に対応します。ASCII文字のみで構成されたファイルを**テキストファイル**、それ以外のファイルを**バイナリファイル**と呼びます。

基本的な考え方：システム内のすべての情報は、一連のビットによって表現されます。データのコンテキストによって、異なるデータオブジェクトを区別します。数値の機械表現は実際の数値とは異なり、真の値に対する有限精度の近似値です。

# 2 プログラムは別のプログラムによって異なる形式へ変換される

高水準C言語—変換—\>低水準機械語命令—パッケージ化—\>実行可能オブジェクトプログラム

```shell
gcc -o hello hello.c
./hello

```

![](https://dreaife-1306766477.cos.ap-nanjing.myqcloud.com/%E5%B1%8F%E5%B9%95%E6%88%AA%E5%9B%BE%202023-01-15%20165458.png)

コンパイルシステム

コンパイルシステム：プリプロセッサ、コンパイラ、アセンブラ、リンカ

- 前処理

	プリプロセッサ(cpp)は、#で始まる命令に基づいて元のプログラムを変更し、ヘッダーファイルの内容をプログラムのテキストに直接挿入します。

	hello.c—cpp—\>hello.i

- コンパイル

	コンパイラ(ccl)は、前の手順で生成された.iファイルを、アセンブリ言語プログラムを含む.sファイルに変換します。

	hello.i—ccl—\>hello.s

- アセンブル

	アセンブラ(as)は.sファイルを機械語命令に変換し、再配置可能オブジェクトプログラムとしてパッケージ化して、バイナリ形式の.oファイルに保存します。

	hello.s—as—\>hello.o

- リンク

	リンカ(ld)は、現在の.oファイルと、呼び出されるライブラリ関数のコンパイル済みオブジェクトファイルを結合し、システムが実行できる実行可能オブジェクトファイルを生成します。

	hello.o+printf.o—ld—\>hello

# 3 コンパイルシステムを理解する利点

1. クエリ性能を最適化する
2. リンク時に発生するエラーを理解する
3. セキュリティホールを回避する

# 4 プロセッサは命令を読み取り、解釈する

## 4.1 システムのハードウェア構成

![](https://dreaife-1306766477.cos.ap-nanjing.myqcloud.com/%E5%B1%8F%E5%B9%95%E6%88%AA%E5%9B%BE%202023-01-15%20171549.png)

システムのハードウェア構成

1. バス

	システム全体を貫く電子的な伝送路の集合であり、情報を表すバイトを運びます。固定長のバイトブロックであるword（ワード）を転送します。ワードを構成するバイト数はシステムによって異なり、4バイト（32ビット）や8バイト（64ビット）など、システムの基本的なパラメータとなります。

	システムバス、メモリバス、I/Oバス

2. I/Oデバイス

	システムと外部との通信を担います。入力用のキーボードやマウス、出力用のディスプレイ、長期保存用のディスクなどがあります。

	I/Oデバイスは、コントローラまたはアダプタを介してI/Oバスに接続されます。

	- コントローラとアダプタの違い

		実装形態が異なります。

		コントローラ：I/Oデバイス自体、またはシステムのマザーボード上にあるチップセット。

		アダプタ：マザーボードのスロットに挿入するカード。

3. 主記憶

	プログラムと、プログラムが処理するデータを保持する一時記憶装置です。

	物理的にはダイナミック・ランダム・アクセス・メモリ（DRAM）チップで構成されます。論理的には線形のバイト配列であり、各バイトには一意のアドレスが割り当てられ、アドレスは0から始まります。

4. プロセッサ

	中央処理装置（CPU）は、主記憶に格納された命令を解釈するエンジンです。

	その中核は、プログラムカウンタ（PC）と呼ばれる1ワードサイズの記憶装置であり、主記憶内の特定の機械語命令（のアドレス）を指します。電源が入ってから、プロセッサはPCが指す命令を繰り返し実行し、PCを更新して次の命令を実行します。

	プロセッサは、命令セットアーキテクチャによって定義される命令実行モデルに従って動作します。このモデルでは、命令は厳密な順序で実行されます。1つの命令の実行には、cpuがpcの指すメモリから命令を読み取り、その命令のビットを解釈し、命令が指定する**単純な操作**を実行し、次の命令を指すようにpcを更新する処理が含まれます。

	上記の単純な操作の種類は多くありません。これらは、**主記憶**、**レジスタファイル**\[それぞれ一意の名前を持つ、複数の1ワード長レジスタで構成された小さな記憶装置\]、**算術論理演算装置**（ALU）\[新しいデータ値やアドレス値を計算する\]を中心に行われます。

	- 単純な操作
		- ロード

			主記憶から1バイトまたは1ワードをレジスタへコピーし、レジスタの元の内容を上書きする

		- ストア

			レジスタから1バイトまたは1ワードを主記憶内の特定の位置へコピーし、その位置にあった元の内容を上書きする。

		- 演算

			2つのレジスタの内容をALUへコピーし、ALUがその2つのワードに対して算術演算を行い、結果を1つのレジスタに保存して、そのレジスタの元の内容を上書きする。

		- ジャンプ

			命令自体から1ワードを取り出してプログラムカウンタ(PC)へコピーし、pcの元の値を上書きする

	形式的には、プロセッサは命令セットアーキテクチャを単純に実装したものですが、実際にはプログラムの実行を高速化するために非常に複雑な仕組みが使用されています。そのため、プロセッサの命令セットアーキテクチャとマイクロアーキテクチャを区別する必要があります。**命令セットアーキテクチャ**は各機械語命令の効果を記述し、**マイクロアーキテクチャ**はプロセッサが実際にどのように実装されているかを記述します。

# 5 キャッシュは重要

以上から分かるように、システムは情報の移動に多くの時間を費やしており、このようなコピー処理がプログラムの動作をある程度遅くしています。

プロセッサと主記憶の速度差を補うために、近いうちに使用される可能性がある情報を保存する**キャッシュメモリ**（cache）が使用されます。L1キャッシュ、L2キャッシュなどは、**スタティック・ランダム・アクセス・メモリ**（SRAM）というハードウェア技術によって実装されます。キャッシュの**局所性**の原理、すなわちプログラムには局所的な領域にあるデータやコードへアクセスする傾向があることを利用します。

キャッシュを利用することで、プログラムの性能を1桁向上させることができます。

その基本的な考え方は、上位層のメモリを下位層のメモリのキャッシュとして使用することです。

# 7 オペレーティングシステムによるハードウェアの管理

プログラムは、オペレーティングシステムが提供するサービスを介してハードウェアにアクセスします。アプリケーションプログラムによるハードウェア操作は、すべてオペレーティングシステムを経由する必要があります。

![](https://dreaife-1306766477.cos.ap-nanjing.myqcloud.com/%E5%B1%8F%E5%B9%95%E6%88%AA%E5%9B%BE%202023-01-15%20212054.png)

コンピュータシステムの階層ビュー

オペレーティングシステムは、制御不能なアプリケーションプログラムによるハードウェアの不正使用を防ぐとともに、複雑で多様なハードウェアデバイスを制御するための単純で一貫した仕組みをアプリケーションプログラムに提供します。これは、いくつかの抽象概念（**プロセス**、**仮想メモリ**、**ファイル**）によって実現されます。

ファイルはI/Oデバイスの抽象化、仮想メモリは主記憶とI/Oデバイスの抽象化、プロセスはプロセッサ、主記憶、I/Oデバイスの抽象化です。

![](https://dreaife-1306766477.cos.ap-nanjing.myqcloud.com/%E5%B1%8F%E5%B9%95%E6%88%AA%E5%9B%BE%202023-01-15%20212428.png)

オペレーティングシステムが提供する抽象表現

## 7.1 プロセス

プログラムの実行中、オペレーティングシステムは、現在のプログラムがプロセッサ、主記憶、I/Oデバイスを独占しているかのような錯覚を提供します。この錯覚はプロセスによって実現されます。

**プロセス**とは、実行中のプログラムに対してオペレーティングシステムが提供する抽象化です。1つのシステムでは複数のプロセスを同時に実行でき、それぞれのプロセスには、各自がハードウェアを独占しているように見えます。

**並行**実行とは、あるプロセスの命令と別のプロセスの命令が交互に実行されることを指します。これはプロセッサがプロセス間を切り替えることで実現され、その仕組みを**コンテキストスイッチ**と呼びます。

**コンテキスト**とは、オペレーティングシステムが追跡する、プロセスの実行に必要なすべての状態情報です。これにはPC、レジスタの現在値、主記憶の内容などが含まれます。単一プロセッサシステムでは一度に1つのプロセスのコードしか実行できないため、別のプロセスを実行する必要がある場合は**コンテキストスイッチ**（現在のプロセスのコンテキストを保存し、新しいプロセスのコンテキストを復元する処理）が必要になります。

![](https://dreaife-1306766477.cos.ap-nanjing.myqcloud.com/%E5%B1%8F%E5%B9%95%E6%88%AA%E5%9B%BE%202023-01-15%20213547.png)

プロセスのコンテキストスイッチ

図に示すように、プロセスの切り替えはオペレーティングシステムの**カーネル**（kernel）によって管理されます。カーネルとは、主記憶に常駐するオペレーティングシステムコードの一部であり、オペレーティングシステムがすべてのプロセスを管理するために使用するコードとデータ構造の**集合**です。アプリケーションプログラムがオペレーティングシステムの機能を必要とすると、カーネルは特殊な**システムコール**（system call）命令を実行して、制御をカーネルへ渡します。カーネルは要求された処理を実行し、その後アプリケーションプログラムへ戻ります。

## 7.2 スレッド

1つのプロセスは複数の実行単位（**スレッド**）で構成できます。各スレッドはプロセスのコンテキスト内で実行され、同じコードとグローバルデータを共有します。マルチスレッドはマルチプロセスよりもデータを共有しやすいため、一般にスレッドのほうがプロセスより効率的です。

## 7.3 仮想メモリ

**仮想メモリ**は、各プロセスに主記憶を独占しているかのような錯覚を提供します。各プロセスから見える一貫したメモリを**仮想アドレス空間**と呼びます。Linuxでは、アドレス空間の最上部の領域にオペレーティングシステムのコードとデータが置かれ、下部にはユーザープロセスが定義したコードとデータが置かれます。

![](https://dreaife-1306766477.cos.ap-nanjing.myqcloud.com/%E5%B1%8F%E5%B9%95%E6%88%AA%E5%9B%BE%202023-01-15%20214623.png)

仮想アドレス空間

- プログラムコードとデータ

	すべてのプロセスにおいて、コードは同じ固定アドレスから始まり、その後にCのグローバル変数に対応するデータ領域が続きます。

- ヒープ

	実行時の**ヒープ**は、`malloc`や`free`などを呼び出すと、実行時に動的に拡張および縮小できます。

- 共有ライブラリ

	空間の中間部分には、C標準ライブラリや数学ライブラリなどの共有ライブラリのコードとデータが配置されます。

- スタック

	**ユーザースタック**はユーザー仮想メモリ空間の上部に位置し、コンパイラが関数呼び出しを実装するために使用します。これも実行時に動的に拡張および縮小できます。関数を呼び出すとスタックは拡張し、関数から戻るとスタックは縮小します。

- カーネル仮想メモリ

	アドレス空間の最上部に位置します。アプリケーションプログラムは、その領域の内容を読み書きしたり、カーネルコードで定義された関数を直接呼び出したりすることはできず、必ずカーネルを介して呼び出す必要があります。

基本的な考え方は、プロセスの仮想メモリの内容をディスク上に保存し、主記憶をディスクのキャッシュとして使用することです。

## 7.4 ファイル

**ファイル**とはバイト列であり、すべてのI/Oデバイスをファイルと見なすことができます。linuxシステムにおける入出力は、Unix I/Oと呼ばれる少数のシステム関数を使用してファイルを読み書きすることで実現されます。

ファイルは、さまざまなI/Oデバイスを扱うための統一されたビューをアプリケーションプログラムに提供します。

# 9 重要なテーマ

## 9.1 Amdahlの法則

システムの一部分を高速化したとき、システム全体への効果は、その部分の重要性と高速化の程度によって決まります。

\$\\alpha\$はその部分の処理時間が全体の処理時間に占める割合、\$k\$は性能向上の倍率です。

\$\$<br>T_\{new\}=(1-\\alpha)T_\{old\}+(\\alpha  T_\{old\})/k = T_\{old\}\[(1-\\alpha)+\\alpha/k\]<br>\$\$

高速化率\$S=T_\{old\}/T_\{new\}\$を計算すると、

\$\$<br>S=\\frac\{1\}\{(1-\\alpha)+\\alpha/k\}<br>\$\$

kが無限大に近づくと、

\$\$<br>S_\{\\infty\}=\\frac\{1\}\{(1-\\alpha)\}<br>\$\$

## 9.2 並行性と並列性

並行性：複数の活動を同時に持つシステムを指します。並列性：並行性を利用してシステムをより高速に動作させることを指します。

1. スレッドレベルの並行性

	プロセスを使用すると、複数のプログラムを同時に実行して並行性を実現できます。この並行性は擬似的なものであり、1台のコンピュータが実行中のプロセス間を高速に切り替えることで実現されます。これにより、複数のユーザーが同時にシステムとやり取りしたり、1人のユーザーが複数のタスクを同時に実行したりできます。

	**マルチコアプロセッサ**は、複数のCPUを1つの集積回路チップ上に統合したものです。

	![](https://dreaife-1306766477.cos.ap-nanjing.myqcloud.com/%E5%B1%8F%E5%B9%95%E6%88%AA%E5%9B%BE%202023-01-15%20223232.png)

	マルチコアプロセッサ

	**ハイパースレッディング**は、同時マルチスレッディングとも呼ばれ、1つのCPUが複数の制御フローを実行できるようにする技術です。ハイパースレッディング対応プロセッサは、サイクル単位でどのスレッドを実行するかを決定できるため、CPUの処理資源をより有効に活用できます。

	マルチプロセッサによるシステム性能の向上：1. 複数タスクの擬似的な並行実行の必要性を減らす。2. アプリケーションプログラムをより高速に実行する（プログラムをマルチスレッド方式で記述する必要がある）

2. 命令レベルの並列性

	プロセッサが複数の命令を同時に実行できることを指します。プロセッサは**パイプライン**を使用して、命令の実行速度を向上させます。命令の実行を複数のステップに分割し、プロセッサのハードウェアを一連のステージとして構成して、各ステージが1つのステップを実行します。各ステージは並列に動作し、異なる命令の異なるステップを処理します。

	スーパースカラプロセッサ—1サイクルあたり1命令を上回る実行速度を持つプロセッサ。

3. 単一命令・複数データ並列性

	プロセッサの専用ハードウェアを使用することで、1つの命令から並列実行可能な複数の操作を生成できます。これを単一命令・複数データ、すなわち**SIMD並列性**と呼びます。主に画像、音声、映像データを処理するアプリケーションの実行速度を向上させるために使用されます。コンパイラがサポートする特殊なベクトルデータ型を使用してプログラムを記述できます。

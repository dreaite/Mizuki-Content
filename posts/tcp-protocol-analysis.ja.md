# **1．実験目的**

- トランスポート層のTCPプロトコルに関する基本概念とパケット構造を理解する
- TCPパケットのヘッダーを分析する
- TCP接続の確立プロセスとTCP接続の切断プロセスを分析する
- `tcpdump`と`wireshark`を使用した`tcp`プロトコルの分析技術を習得する。

## **2．実験環境**

- ハードウェア要件：Alibaba Cloud ECSクラウドサーバー1台。
- ソフトウェア要件：Linux／Windowsオペレーティングシステム

## **3．実験内容**


TCPはコネクション型のプロトコルであり、信頼性のない相互接続ネットワーク上で、信頼性の高いエンドツーエンド通信を提供する。TCP/IPプロトコル群の中核となるプロトコルである。


TCPではパケット伝送の信頼性を保証するため、各パケットにシーケンス番号を付与する。このシーケンス番号により、受信側に到着したパケットが順序どおりに受信されることも保証される。その後、受信側は正常に受信したバイトに対応する確認応答（ACK）を返す。送信側が適切な往復遅延時間（RTT）内に確認応答を受信しなかった場合、対応するデータは消失したものと見なされ、再送される。


`wget`を使用して新疆大学のホームページ`www.xju.edu.cn`をダウンロードし、それと同時に`tcpdump`でパケットをキャプチャする。`wireshark`を使用してTCPデータパケットのヘッダー、接続確立時の3ウェイハンドシェイク、および接続切断時の4ウェイハンドシェイクを分析する。

- 実験結果の分析を通じて、TCPパケットの構造がどの部分で構成され、それぞれにどのような機能があるかを確認する。

TCPパケットは一般に次の部分に分けられる：

1. ポート番号：同一コンピューター上の異なるアプリケーションプロセスを識別するために使用される。

1.1 送信元ポート：送信元ポートとIPアドレスは、パケットの返信先アドレスを識別するために使用される。


1.2 宛先ポート：受信側コンピューター上のアプリケーションインターフェースを指定する。


TCPヘッダー内の送信元ポート番号と宛先ポート番号は、IPデータグラム内の送信元IPアドレスおよび宛先IPアドレスとともに、1つのTCP接続を一意に特定する。

1. シーケンス番号と確認応答番号：TCPの信頼性の高い伝送を実現する重要な部分である。シーケンス番号は、このセグメントで送信されるデータグループの最初のバイトの番号であり、TCP伝送の順序性を保証する。確認応答番号、すなわちACKは、次に受信を期待するバイトのシーケンス番号を示し、その番号より前のすべてのデータが正しく受信されたことを表す。
2. データオフセット／ヘッダー長：4bits。ヘッダーにはオプションが含まれる場合があるため、TCPヘッダーの長さは一定ではない。このフィールドは、実際にはセグメント内におけるデータ領域の開始オフセットを示す。
3. 予約：将来、新しい用途を定義するために予約されており、現在は通常0に設定される。
4. 制御ビット：URG ACK PSH RST SYN FINの計6個で、それぞれのフラグが1つの制御機能を表す。

5.1 URG：緊急ポインタフラグ。1の場合は緊急ポインタが有効であり、0の場合は緊急ポインタを無視する。


5.2 ACK：確認応答番号フラグ。1の場合は確認応答番号が有効であり、0の場合はパケットに確認応答情報が含まれていないため、確認応答番号フィールドを無視する。


5.3 PSH：プッシュフラグ。1の場合はプッシュフラグ付きのデータであることを表し、受信側に対して、このセグメントを受信した後にバッファー内で待機させず、できるだけ早くアプリケーションへ渡すよう指示する。


5.4 RST：接続リセットフラグ。ホストのクラッシュやその他の原因により異常が発生した接続をリセットするために使用される。また、不正なセグメントや接続要求を拒否するためにも使用される。


5.5 SYN：シーケンス番号同期フラグ。接続確立プロセスで使用される。接続要求においてSYN=1、ACK=0の場合は、そのデータセグメントが確認応答フィールドを相乗りさせていないことを示す。接続応答では確認応答が相乗りし、SYN=1、ACK=1となる。


5.6 FIN：終了フラグ。接続を切断するために使用される。1の場合、送信側に送信するデータがなくなり、自身のデータストリームを閉じたことを表す。

1. ウィンドウ：スライディングウィンドウのサイズ。受信側のバッファーサイズを送信側に通知し、送信側のデータ送信速度を制御することでフロー制御を実現する。
2. チェックサム：パリティチェック。このチェックサムは、TCPヘッダーとTCPデータを含むTCPセグメント全体を16ビット単位で計算したものである。送信側で計算および格納され、受信側で検証される。
3. 緊急ポインタ：URGフラグが1に設定されている場合にのみ有効である。TCPの緊急モードは、送信側が相手側へ緊急データを送信する方法の一つである。
4. データ部：伝送される情報。

### **4.2** **接続確立時の3ウェイハンドシェイクの分析**

- 3ウェイハンドシェイクのフラグビットとシーケンス番号を分析する

![YrHyu594bim7VpD.png](https://s2.loli.net/2022/05/15/YrHyu594bim7VpD.png)


1回目のハンドシェイク：クライアントはSYNフラグを設定したパケットをサーバーへ送信し、Seq=0（x）を設定してサーバーへの接続を要求する


2回目のハンドシェイク：サーバーはクライアントにSYNで応答し、SYNフラグとACKフラグを設定するとともに、Seq=0（y）、ACK=1（x+1）を設定する


3回目のハンドシェイク：クライアントはサーバーのSYNパケットを受信すると、ACK=1（y+1）およびACKフラグを設定したパケットで応答する


### **4.3** **接続切断時の4ウェイハンドシェイクの分析**

- 4ウェイハンドシェイクのパケットフラグとシーケンス番号を分析する

![O6n4rQpIR8DHjsL.png](https://s2.loli.net/2022/05/15/O6n4rQpIR8DHjsL.png)


1回目のハンドシェイク：クライアントはFIN、Seq=166、Ack=7725をサーバーへ送信する


2回目のハンドシェイク：サーバーはACK、Seq=7725、Ack=167を返信する


3回目のハンドシェイク：サーバーはFIN、Seq=7725、Ack=167を送信する


4回目のハンドシェイク：クライアントはACK、Seq=167、Ack=7726をサーバーへ返信する

- Wiresharkで3つのパケットしかキャプチャされなかった理由

図から、本来4ウェイハンドシェイクであるはずの切断処理が3回になっていることが分かる。これはTCPが全二重通信であるためである。ClientはServerへ送信する新しいデータがなくなった時点でFINを送信し、Clientから相手側のServerへのデータ伝送が終了したことを通知できる。ただし、この時点でも相手側のServerは引き続きClientへデータパケットを送信できる。そのため、両方向のデータ伝送終了は時系列的に独立しており、大きな時間差が生じる可能性がある。この場合、接続を完全に切断するには最低でも2+2=4回のハンドシェイクが必要となる。しかし、ServerがClientからFINパケットを受信した時点でClientへ送信するデータがない場合、ClientへのACKパケットとServer自身のFINパケットを1つのパケットにまとめて送信できる。このため、4ウェイハンドシェイクが3回になる。
